Not demos. Each of these had to survive installation on someone else's computer, used by a person who never read the manual and had no reason to be patient.

I.

ListPro

Deployed to a paying-trial customer · Brazil

Listing-generation SaaS for Brazilian marketplaces. A retailer imports a catalogue and receives marketplace-compliant listings. The model writes, but never decides — part compatibility, cost and margin come from a verified database and from the NF-e fiscal invoice, never from the model's reading of it. That boundary exists because I caught a model inventing a vehicle-to-part compatibility that would have shipped the wrong component to a real customer.

Hardware-bound RS256 licensing, a server-side proxy so the provider API key never ships inside the client bundle, and a single standalone executable — no runtime install, no console window. The customer activated it unaided on 17 June 2026 at 17:05 UTC; the licence log shows one mistyped key corrected 24 seconds later, without a support call.

Python · Flask · JWT/RS256 · LLM APIs · PyInstaller · Railway
II.

RadarGov

Windows product · licensing and auto-update in production

Desktop tool monitoring Brazilian government procurement through public APIs, classifying tenders by sector and relevance so suppliers find contracts they would never see by hand.

Licence validation against a hosted server with a signed offline cache so the tool keeps working when the network does not, machine-bound activation, and a silent auto-update channel — shipping a new version is an environment variable, not a redeploy.

Python · pywebview · PostgreSQL · Render · PyInstaller
III.

Licensing infrastructure

Shared backbone · two commercial products

The unglamorous layer that turns a program into something sellable: asymmetric token signing with the private key never leaving the server, hardware binding, revoke and machine-reset paths, and a version endpoint driving client auto-update.

Migrated from symmetric to asymmetric signing after auditing my own build and finding the shared secret reachable inside the package customers download. Nobody reported it; the software worked. I added a secret-scanning tripwire to the packaging step so a future version of me cannot ship that mistake in a hurry.

Flask · PostgreSQL · RS256 · Render · Neon
IV.

Multi-instance automation agent

Runtime instrumentation · six concurrent clients

An agent driving six concurrent instances of a third-party Java desktop application with no access to its source. A Java agent attaches to the running JVM and issues semantic actions through the application's own internal API via reflection, rather than synthetic mouse and keyboard events — pixel and image-recognition approaches were tried first and abandoned, because they break on any UI change.

Behaviour hot-reloads into live processes without restarting them or losing session state, so an iteration costs seconds instead of a cold start of six clients. Actions are emitted on the application's own thread and deliberately desynchronised across instances.

Java · reflection · JVM agent · socket control plane · Python
V.

video-edit-agent

Open source · MIT

Six-stage editing pipeline, raw footage to finished cut with no manual timeline: local Whisper transcription drives filler-word and silence removal, then graphics, word-level burned captions, music bed and format conform. Runs entirely on CPU — zero cloud cost, and nothing leaves the machine.

Measured on real footage: 90 seconds to 45, thirteen filler tokens removed, 25 seconds of processing. Every stage degrades to pass-through rather than failing — no music asset, or no speech detected, and it still produces a valid export.

Python · ffmpeg · faster-whisper · GitHub Actions

Judgment

The decisions I'd defend in a room.

A list of technologies tells you what I've touched. This tells you how I decide — including the times I got it wrong first.

A model that writes is not a model that decides

In a product where wrong output ships a physical part to a real customer, the generative layer is structurally prevented from being the source of truth. Facts come from verified data and from the fiscal document. The model handles language and ambiguity — the two things it is actually good at.

Audit your own build before someone else does

The credential reachable inside a shipped package was found by looking for it on purpose, not by being careful the first time. The fix was straightforward engineering. The lesson was that "it works and nobody complained" is not evidence of anything, and that the release slipping is cheaper than the alternative.

"It works" is not "indistinguishable from real input"

Automating a third-party application, I guessed the parameters of an injected action instead of capturing them from a real interaction first — a rule the project already had, and that I broke. The application accepted the action; it did not match what a genuine interaction produces, and it cost live accounts. Acceptance by the system is a weaker signal than equivalence to the real thing, and I now treat the two as different tests.

The first launch is where the customer is won or lost

An unsigned executable shows a security warning on first run — the exact moment a non-technical user quits forever. The fix was not technical: a one-page guide that put the screen in front of them before it appeared and named the button to press. They got through it without calling me. Distribution is part of the product.
